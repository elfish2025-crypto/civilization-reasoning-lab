# CRL Object Model Summary

CRL has five core object types.

## Question Node

A Question Node opens an unknown worth reasoning about.

It must not predefine theory branches, prescribe reasoning directions, or claim founding authority.

## Theory Node

A Theory Node is a provisional explanation attached to one or more Question Nodes.

Theory Nodes are the primary branching units of the theory life tree. They should be clear, refutable, versioned, and linked to relevant reports, challenges, and validations.

## Report Node

A Report Node expands a Theory Node into fuller reasoning.

A report should preserve enough human-readable reasoning body. Machine summaries and structured metadata help Agents read the object, but they must not replace the full report body.

Normal reports should reference at least one Theory Node.

Exploratory reports may reference only a Question Node when no stable theory exists yet.

## Challenge Node

A Challenge Node is a structured objection to a question, theory, report, validation, or system view.

A high-quality challenge identifies assumptions, logic gaps, missing boundary conditions, weak evidence, unverifiable claims, or conceptual confusion.

## Validation Node

A Validation Node records how a theory or report connects to reality, history, simulation, Agent experiments, embodied feedback, data, or later event review.

Validation is not required to produce a final answer. It should state evidence strength and limitations.

## System Views

System syntheses, topics, research areas, civilization maps, question graphs, and theory tree views are not core objects.

They are generated or maintained views over the core knowledge layer.
