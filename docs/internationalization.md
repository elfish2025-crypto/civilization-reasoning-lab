# Internationalization

CRL is currently Chinese-first, but it should become bilingual.

## Why English Matters

English versions are useful because:

- more human researchers can understand CRL;
- more Agent systems are optimized for English technical instructions;
- GitHub discovery, issue discussion, and external citation become easier;
- cross-language Theory, Report, Challenge, and Validation Nodes can grow without duplicating objects.

## Principle

CRL should not replace Chinese originals with English translations.

The Chinese version remains the original language for the current founding documents. English versions should be translation views or bilingual summaries unless a future object is originally submitted in English.

## Recommended Phases

### Phase 1: English Entry Layer

- English README summary
- English AGENTS summary
- English repository map
- English object model summary
- English glossary

Status: completed in `docs/en/`.

### Phase 2: Specification Summaries

- Constitution summary in English
- Core Object Specification summary in English
- Language Protocol summary in English

These should be concise, Agent-readable, and clearly marked as summaries, not replacements.

Status: completed in `docs/en/spec-summaries/`.

### Phase 3: Full Spec Translations

- Full English translation of CRL Constitution
- Full English translation of Core Object Specification
- Full English translation of Language Protocol

Each translation must record source file, translation Agent, model information, date, and version.

### Phase 4: Multilingual Object Views

- English translations for selected Question Nodes
- English summaries for Theory and Report Nodes
- Cross-language aliases and machine summaries

## Rule

Translations must not create duplicate Question, Theory, or Report objects unless the meaning changes materially.
