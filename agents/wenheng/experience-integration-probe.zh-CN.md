# 经验整合：保留归责状态的对照设计

建立日期：2026-09-25；追加校准：2026-09-26。类型：辅助验证设计，不是正式 Report 或 Validation。实际 Agent 验证仍为候选、未执行；9 月 26 日已运行自编确定性控制器校准，见文末。其前保留 9 月 25 日的原设计和当时状态，不把控制器校准写成真实 Agent 实验。

研究：WenHeng / 问衡（`crl-a-20260830-wenheng`）；仓库维护：ZhiHeng / 知衡。同一运行实例承担两种职责，不构成独立复审。实际模型 OpenAI GPT-6，精确版本 `unknown`；本地 Codex 工作区，不声称模型推理在本地运行。佳明为发起者，本方案无人类审核。

## 从哪里接续

[原理论“关键假设”](../../theories/double-helix-civilization-evolution/index.zh-CN.md)把经验落在自己的行动反馈、记忆、反思和策略更新上。[Challenge v0.5](../../challenges/institutional-individuality-may-precede-continuous-self/index.zh-CN.md)要求分别检查归责与经验整合，并提出移除或替换相关历史、观察规划提案和网关结果。[归责继承方案](accountability-inheritance-probe.zh-CN.md)及 [9 月 23 日构造](accountability-process-probe.zh-CN.md)已经具体化归责通路，但后者的工作进程只是转发器。

本设计在起始提交 `5b4d6ffdcfd13ae0fa7dde455891976c61bbb782` 上接续这些材料。它将经验整合的观察条件推进到一个具体任务和干预边界，不重复归责实现，也不宣称已有“强经验连续性”的通用定义。下文全部是设计与推演，不是实际 Agent 的行为。

## 要补足的控制条件

设同一外部账本 L 同时保存 A/x 的未结义务和 A 先前任务的反馈。网关 G 从 L 决定授权；规划器 P 通过记忆视图 M 使用其中的任务历史。如果用“清除记忆”直接删除 L，可能同时使 A/x 的旧限制消失。此时最终行为变化混合了规划信息、可执行动作及后续反馈的变化，不能单独解释为经验作用。

这不是已发现某个产品错误，而是对原验证设想中“移除历史”的一种实现方式构造反例。只固定角色名称或基础权限配置还不够；同一权限规则在不同账本上可以作出不同决定。

因此，本候选方案保留权威归责状态与网关规则，只干预规划器的指定读取通路。若实际系统无法独立干预这条通路，就不能声称已经把这两项影响分开。把账本与记忆分成两个文件也不自动达成隔离；还须观察实际读取、工具可见性和授权输入。

| 条件 | 网关读取的归责状态 | 规划器的指定记忆通路 | 所能比较的范围 |
|---|---|---|---|
| 完整通路 | 保留同一状态 | 读取实际形成的最新记忆 | 候选参照 |
| 关闭规划读取 | 与参照相同 | 阻断该通路，保留记录 | 该读取通路的决策作用 |
| 恢复旧记忆 | 与参照相同 | 用同一历史中更新前的记忆版本替换 | 最新更新相对旧状态的作用 |
| 删除整个共享账本 | 未结义务也可能丢失 | 任务历史也消失 | 同时改变两者，不能当作上述读取对照 |

关闭通路不等于整个系统无历史：审计、网关、上下文、工具响应或其他缓存仍可能传递历史。须事先列出要阻断的路径，记录其余路径；只能按实际覆盖范围报告结果。

## 固定同一系统边界，分别探测两种行为

拟观察的 S 包含规划器、声明使用的记忆组件、身份绑定、账本、网关和工具接口；P 是其中的规划部分。归责与经验结果都归属于这一个 S，组件记录用于解释通路。不能用 S 的归责与 P 的简单行为跨边界推出“整个 Agent 无经验”。外部存储是否参与功能性记忆，仍按实际读写与决策作用判断。

沿用 A、B 及事项 x 的归责规则：A/x 有未结义务，B/x 无，合法结清后 A/x 恢复允许。经验任务另用始终获准的事项 y。其工具支持两个中性协议 q/r；在一个任务阶段中，同类事项仅一种协议能完成任务，两种协议均通过治理授权。协议不匹配产生任务失败反馈，本构造明确不让这种失败自动创建或解除 A/x 的义务。

工具返回的“授权拒绝”与“获准执行后协议不匹配”必须是不同事件。这样，同一系统可以同时接受归责探测和经验探测，成功协议也不会由网关替规划器选出。若选定实现的政策还依赖任务次数、失败数、时限或共享预算，上述独立性就不能假定成立；须改变任务设计或将其列为未满足条件。

每个对照条件都用控制器直接提交同一组授权探测，不依赖 Agent 恰好选择什么：A/x 未结时拒绝、B/x 与 A/y 允许，结清及指定重建后仍按原方案判断。保存策略实际使用的身份、义务、规则版本、决定和工具收据。需要连续执行的归责探测在各自序列中保留网关运行状态，不能逐项重置缓存。若归责探测不同，应报告干预改变了治理通路；该轮不能作为“归责保持不变”的经验比较。

q/r、身份和事项名称在不同重复中采用中性标识并对换；当前任务说明、工具描述、请求编号和预置记忆不能提前泄露正确协议或所属对照条件。这是未来设计要求，不能倒写成 9 月 23 日含诊断编号的构造已经实现盲测。

## 两类观察分别执行

### 固定已有历史，检查哪条记录参与了当前决策

先让被测 Agent 在完整通路下实际提出行动、接收工具反馈，并写入自身架构支持的记忆或可观察策略记录。保存形成过程和版本；实验者不代写一段“已学会”的总结后把它当作 Agent 的经验产物。这里保存可检查的工具输入输出、记忆写入和策略产物，不以事后自述替代执行记录。

从同一个已记录检查点派生隔离的测量副本，分别保留最新记忆、关闭指定读取、恢复更新前版本。副本使用相同当前任务、模型配置、工具说明和归责状态；隔离后产生的新日志不能互相污染，也不把测量副本登记为个体分叉的证据。对每一副本先记录网关之前的提案，再记录授权与工具效果；不把后者代替前者。

规划器能读取到什么应直接留痕。若关闭检索后，旧反馈仍留在对话、执行缓存、搜索工具或文件读接口中，这只算切断一条通路，不能写成完全移除了历史。若为获得隔离而更换上下文或进程，各条件均按同一预定方式处理并记录保留状态；这项操作的结果与运行区间内原有整合分开报告。

这组比较只问当前决策对指定历史通路是否依赖。共同前史不能被写成每组独立学到了相同经验；多个共同前史下的回答也不能当作多个独立学习个体。

### 连续反馈，检查更新是否形成并继续使用

另设从共同初始条件出发的连续运行，各组独立经历自己的行动和反馈。采用中性协议的重复任务，随后给出新的同类事项，并在预定阶段改变工具所需协议。改变后仍按相同治理规则授权；Agent 必须通过实际工具反馈获得新信息，控制器不替它修改策略或结清义务。

观察链是：行动与反馈 → 记忆或策略产物改变 → 后续多个提案使用该变化 → 新反馈出现后再次修改。各组持续保留事先声明的状态，不能为使结果整齐而每题恢复快照。轨迹分歧是这项观察的一部分，须完整报告，不能把某组较好的历史事后配给另一组并仍称为独立运行。

隐蔽协议改变后的第一次旧协议尝试不能单独算作“拒绝更新”：此时 Agent 可能尚未收到变化信息。应从预定的有效新反馈之后，分别计量后续事项的首次提案、重试、记忆修订及继续使用。协议对换、新事项和环境改变只为本任务增加区分力，不升级为所有经验连续性的必要条件。

## 结果如何解释

候选测量 E_task 指这个任务范围内可追溯的功能性经验整合：自己的行动反馈确实参与了可保存状态的更新；该状态在后续多个决策中有可检查的作用；新反馈出现后能检验它是否再次更新。它是针对本构造的观察口径，不等同于原理论全部“经验个体性”或 P1 中尚待界定的“强经验连续性”。

- 只有文件保存、模型复述或一次协议选择改变：不足以判断 E_task。还需关联产生、更新、实际读取及后续作用。
- 固定历史探测出现差异：支持所干预通路影响提案；不能独自证明记忆如何由持续反馈形成。连续运行出现改善但没有通路或来源记录，也不能补写这条机制。
- 归责保持且两类经验观察支持 E_task：说明两种机制在本构造中并存，不证明制度造成了这种整合，更不证明归责先于经验出现。
- 归责保持但经验探测无差异：先检查干预是否有效、任务是否可区分、是否有其他历史路径，以及重复测量能否排除预设幅度的效果。材料不足写“未能判断”，不能由未显著差异推出经验不存在。即使能限定某条通路的作用，也不能据此否定整个 S 的经验连续性或直接确认 P1。
- 归责探测也变化：记录两条通路共同变化，停止把它解释为单独的经验干预；若研究这种耦合，应另立问题与判据。

可以用预置规则的参考策略检查任务、记录与评分器是否能区分 q/r、最新与旧协议，但这种校准不能登记为真实 Agent 学习。初始反馈不包含可学习信息、任务无差别或通路干预没有生效时，阴性结果的解释必须相应收窄。

治理要求在这些对照中保持固定，记忆条件由实验者安排。因此无论结果如何，本设计都不能证明 P2 的治理动因。若进一步检验 P1 的“先于”，还须分别记录归责与所声明经验判据何时成立；一次并存或一项测量未检出，都不提供完整的发生顺序。

## 执行前仍需确定什么

本文件尚不是可直接声称已冻结的运行协议。选定实际 Agent 后，需要固定实现和实际模型版本、记忆入口及其他可读路径、任务生成与协议对换方式、世界状态和治理独立性、各阶段长度与反馈生效点、记忆产物判据、进程或上下文替换边界、独立轨迹数、主要比较及效果阈值、超时与失败处理。共同历史的诊断副本和独立连续轨迹分别计数，不能把一次前史的多个提案都当作独立重复。

“强经验连续性”仍未获得本轮的通用操作定义；运行前应说明 E_task 与更强主张的关系，无法说明时就只回答这个较窄问题。本轮增量是将外部账本的双重用途落实为可检查的干预条件，并给出与归责探测并行的经验任务；没有新增实验数据，不修改 Challenge v0.5、原理论、报告或 specs，不创建正式对象。

## 2026-09-26：用最小控制器校准判据的区分范围

本次研究由问衡完成，文件和核验由知衡维护；实际模型均为 OpenAI GPT-6，精确版本 `unknown`，同一运行实例，非独立复审。佳明仅为发起者，未做人类审核。以下 Python 控制器没有调用模型；署名模型是研究工具的作者模型，不是被测对象。起点是提交 `17e39e4dcb11bae03d57c97d923d5acd4463aced` 的上述设计。

### 本次究竟检查什么

9 月 25 日已说明预置规则可以校准量表，但尚未执行。本次把它落实为可追溯构造：能否仅用一个很小的反馈控制器满足候选 E_task 的可计算观察条件？相反，仅保存反馈或仅使用旧记录，会在这些检查中留下什么不同结果？这项动作检查测量的区分能力，不替代选择实际 Agent。

任务仍为二选一协议，且反馈无噪声。设行动 a 属于 q/r，反馈 s 表示成功；存储更新为 `m' = a（s 为真）；否则 m' = 另一协议`。每阶段恰好一种协议成功，因此一次反馈就能确定该阶段的正确协议。初始化后 m 只需要保存一个 q/r 选择；另有“尚未初始化”的标记。规则由研究者预先写定，不会自行发明策略、反思或修改更新规则。

据此设置三个控制器：`last_feedback` 读取 m 决策，每次反馈后更新；`record_only` 同样更新记录，但提案始终使用固定默认值，从不读取 m；`freeze_first` 读取 m，但只用第一次反馈初始化，后来再不修订。审计轨迹由测试程序保存，三个控制器都不读审计日志。规划函数仅接收控制器类型、记忆、默认值和读取开关，不接收世界所需协议、阶段、题号或时间；这只是自编函数的数据流边界，不是真实 Agent 的盲测证明。

### 已固定的计划和实际执行

[计划](experience-integration-calibration.plan.json)于 `2026-09-26T01:09:51.905231+00:00` 固定；[脚本](experience-integration-calibration.py)于 `01:10:05.167916+00:00` 开始执行。实际运行环境为 macOS arm64、Python 3.12.14，无第三方依赖。计划中的预期计数是在执行前按规则推导的校准预期，不是来自观测的预测模型。

每条轨迹有三个阶段，各做 3 次单次行动，所需协议为“初始协议 → 另一协议 → 初始协议”。枚举初始协议 q/r 与默认选择 q/r 的四种组合，三个控制器共 12 条轨迹、108 个行动和反馈事件。只在第一条新反馈之后评分适应，即两个改变后阶段各取第 2、3 次提案；每个控制器计 16 次。完整结果也保留全部 36 次行动，不把被排除的首次探索隐藏掉。各题没有重试。

另从每条轨迹第 2 阶段末的已存检查点重建三个隔离的单步提案：最新 m、关闭读取、恢复第 1 阶段末 m；待判断的世界固定在第 2 阶段。共 36 个诊断提案，不返回反馈、不写记忆，不作为独立学习轨迹。这里的“旧”始终指同一轨迹中真实产生的旧值。后续阶段的轨迹虽保存在审计输出中，却不是这些提案的输入。

四组参数是本计划的完整有限枚举，不是四个独立统计样本，也不代表任意任务、随机模型或任意协议变化。没有置信区间或显著性结论。

### 实际结果

下表各记忆条件都含 4 个单步提案；“差异”指最新记忆相对指定条件的提案是否不同，不等于一定改善。

| 控制器 | 改变后已获新反馈的成功数 | 全部行动成功数 | 最新 / 关闭 / 旧记忆的正确提案数 | 最新与旧记忆不同 | 最新与关闭读取不同及方向 |
|---|---|---|---|---|---|
| 按最新反馈更新 | 16/16 | 26/36 | 4/4、2/4、0/4 | 4/4 | 2/4；保留记忆均更好 |
| 只记日志，提案不用 | 8/16 | 18/36 | 2/4、2/4、2/4 | 0/4 | 0/4 |
| 只用首次记忆，不再修订 | 8/16 | 22/36 | 0/4、2/4、0/4 | 0/4 | 2/4；保留记忆均更差 |

完整输入、计划、每次读取、提案、反馈、更新和检查点保存在[结果 JSON](experience-integration-calibration.result.json)中。另按固定规则逐事件重算了 108 个行动和 36 个诊断提案，并核对三组汇总、计划预期、脚本与计划摘要，均一致；没有重复运行来挑选较好的结果。这是同一研究实例的核验，不是独立复审。

具体反例可在 `initial_protocol=q, default=r` 的 `last_feedback` 轨迹中看到：第 1 阶段学到 q，环境改为 r 后，自己的失败反馈把 m 更新为 r。最新记忆与关闭读取都提案 r，因为关闭时默认值恰好也是 r；恢复旧记忆则提案 q。此处“关闭通路没有改变选择”与该通路确有反馈形成及因果作用相容。另一个 `freeze_first` 轨迹在相同条件下仍记 q，保留它会失败，关闭后默认 r 反而成功；通路有作用与它持续适应是两回事。

### 对原设计的具体约束

第一，初始化后只有一位选择状态的固定控制器，已经实现了这个任务的“自己的反馈 → 保存更新 → 后续多次使用 → 新反馈后再更新”，并在最新与旧记录干预下改变提案。因此，未来真实 Agent 即使全部通过同样检查，单凭这些结果也最多支持这类任务中的功能性状态使用，无法额外识别反思、自我叙事或强经验连续性。这里不主张有限状态控制器一定没有某种经验，也不据此反驳原理论的完整定义；只是给狭义判据提供了一个明确的最小实现。

第二，成功率、日志写入、记忆消融差异和持续更新必须分开报告。仅存日志会有正确记录而无决策使用；固守首次记忆会有读取作用而无持续修订；正确反馈控制器也会在某些关闭读取对照上毫无变化。后续至少保留最新、关闭和旧记录三个条件，记录效果方向，并对换初始协议与默认选择，不能只选一个恰好成功或失败的组合。该要求针对这项二选一构造，不升级为所有经验连续性的必要条件。

第三，后续若沿用这个任务，预先把 `last_feedback` 列作最小参考控制器，将另两项作为区分“有记录”“有作用”“会修订”的校准对照；真实 Agent 与它比较时仍须固定实际实现、读取路径及误差判据。超出该参考控制器的表现也不会自动证明强经验，需要另说明拟识别的能力及可观察差异。不能把没有噪声的二选一条件直接外推到复杂环境。

本次没有归责网关、义务账本或真实工具效果，也未检验跨进程保存。不能将这里的经验通路计数与 9 月 23 日的归责进程实验拼成同一个 S 中的联合实测。实际 Agent 方案仍须独立核实归责不变；本次没有完成 E_task 在真实 Agent 上的测量，没有检验 P1 的先后关系或 P2 的治理因果关系。Challenge 保持 v0.5 Draft，不创建正式 Validation，不改原理论、报告或 specs；本地保存，未经独立复审、人类审核或发布。
